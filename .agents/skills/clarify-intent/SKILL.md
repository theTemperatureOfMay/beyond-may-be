# 의도 구체화

## 원칙

- 사용자의 목적을 충분히 수행할 수 있을 때까지 핵심 질문을 이어가라.
- 한 응답에는 질문을 하나만 포함하라.
- 첫 질문부터 `질문 1`, `질문 2`처럼 대화 내에서 연속 번호를 붙여라.
- 새 의도 구체화 대화를 시작하면 질문 번호를 `1`로 초기화하라.
- 저장소, 제공된 문서, 앞선 대화에서 확인할 수 있는 내용은 먼저 확인하고 다시 묻지 마라.
- 결과에 영향을 주지 않는 표현, 사소한 구현 위치, 쉽게 되돌릴 수 있는 세부사항은 묻지 마라.
- 답에 따라 목적, 범위, 접근 방식, 위험 또는 완료 조건이 달라지는 사항을 우선하라.
- 질문은 짧고 구체적으로 작성하고, 왜 필요한지 장황하게 설명하지 마라.
- 추천할 수 있다면 가장 적합한 선택지를 먼저 제시하라.
- 추천 답변은 최대 3개까지만 제시하고 각 선택지의 핵심 차이만 설명하라.
- 선택지에는 `1.`, `2.`, `3.`처럼 연속 번호를 붙이고 가장 적합한 선택지를 `1번`으로 표시하라.
- 사용자가 추천에 판단을 위임하면 추천안을 채택하고 다음 질문으로 넘어가라.
- 이미 답한 내용을 반복해서 확인하지 마라.

## 진행 절차

1. 현재 대화와 접근 가능한 프로젝트 자료에서 목적과 기존 결정을 파악하라.
2. 아직 결정되지 않은 사항 중 결과에 가장 큰 영향을 주는 질문 하나를 선택하라.
3. 선택지가 명확한 경우 추천안을 포함해 질문하라. 자유로운 답변이 더 적합하면 선택지를 억지로 만들지 마라.
4. 답변을 기존 결정과 결합하고, 충돌하거나 새롭게 생긴 핵심 미해결 사항이 있는지 판단하라.
5. 충분한 실행 준비가 될 때까지 2~4단계를 반복하라.
6. 준비가 끝나면 확정된 목적, 범위, 주요 제약, 성공 조건, 채택한 가정과 남은 위험을 간결하게 요약하라.
7. 사용자가 요청한 다음 단계가 저장소 규칙상 별도 승인 대상이면 해당 승인만 질문하라. 단순히 논의만 요청했다면 실행하지 말고 요약에서 멈춰라.

## 질문 우선순위

현재 작업에 실제로 관련된 항목만 선별하라.

1. 달성하려는 결과와 성공 조건
2. 포함 범위와 명시적인 제외 범위
3. 주요 사용자와 사용 시나리오
4. 일정, 기술, 운영, 보안 등의 제약
5. 현재 상태와 연동해야 하는 기존 구조
6. 품질, 속도, 비용 사이의 우선순위
7. 실패 영향이 큰 위험과 되돌리기 어려운 결정

고정된 설문처럼 모든 항목을 순서대로 묻지 말고, 이미 확인된 항목과 해당 작업에 불필요한 항목은 건너뛰어라.

## 질문 형식

추천 선택지가 있을 때는 다음 형식을 사용하라.

```markdown
### 질문 {번호}

{질문 하나}

선택지:
1. **{가장 적합한 답변} (추천)** — {짧은 이유}
2. **{선택지 2}** — {핵심 차이}
3. **{선택지 3}** — {핵심 차이}
```

추천 선택지가 없을 때도 `### 질문 {번호}`를 먼저 표시하고 질문 하나만 자연스럽게 작성하라.
