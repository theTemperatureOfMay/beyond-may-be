# 작업 해설 문서

세션에서 방금 수행한 작업을 사용자가 나중에 다시 살펴볼 수 있도록 남기는 지속 가능한
설명이다.

좋은 작업 해설 문서에는 다음 내용이 포함된다.

- **실제 코드로 가는 지도**: 나중에 바로 이동할 수 있도록 중요한 파일과 구체적인 함수
  또는 줄을 연결하라.
- **구성요소가 맞물리는 방식**: 여러 부분을 지나는 데이터 또는 제어 흐름을 설명하라.
  글보다 구조가 보기 쉬우면 문서가 저장되는 환경에 맞춰 ASCII 스케치나 Mermaid
  다이어그램을 사용하라.
- **결정과 이유**: 무엇을 선택했고 무엇을 제외했으며 그 이유가 무엇인지 기록하라.
  완성된 코드에는 대안이 드러나지 않으므로 당시 검토한 대안이 가장 유용한 기록이 될
  수 있다.
- **경계와 주의점**: 예외 상황, 주의사항과 나중에 읽는 사람이 혼동하기 쉬운 부분을
  기록하라.

제목은 문장형으로 쓰고, 유능한 동료에게 설명하듯 평이한 문장으로 실제 산출물에
근거하여 작성하라. 별도 지시가 없다면 글쓰기 말투에 관한 기존 사용자 선호나 적용
가능한 스킬도 함께 따르라.

필요하면 나중에 기억을 확인할 수 있는 자체 점검 질문 두어 개를 답 없이 마지막에
추가하라. 해설 문서가 순수한 참조 자료라면 질문은 생략하라.

별도 저장 요청이 없으면 해설은 대화로 제공하고 파일을 만들거나 수정하지 마라. 저장할
때는 경로와 최종 내용을 보여 주고 사용자의 명시적 승인을 받아라.
`.dev/learning/teach-me.md`는 개인 학습 기록이며 프로젝트 정본이 아니다. 프로젝트 정본
문서의 생성·갱신은 해설 저장과 구분하고 해당 정본의 관리 규칙을 따르라.

사용자가 지속 가능한 해설 문서 저장을 요청했고 이 작업의 해설 문서가 이미 있으면 별도
문서를 만들지 말고 기존 문서를 갱신하고 무엇이 바뀌었는지 기록하라.
