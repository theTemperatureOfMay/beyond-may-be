# 변경 영향 검사

변경이 관련 정본과 영향 대상에 일관되게 반영됐는지 수동으로 검사한다. 이 스킬은
자동 수정·커밋·PR 작성·CI 등록을 하지 않는다.

## 검사 원칙

- 먼저 `AGENTS.md`, `docs/index.md`, `docs/harness/change-impact-map.md`,
  `docs/harness/completion-criteria.md`를 읽는다.
- `.env`, credential·secret·인증서·개인 키와 같은 보호 파일은 읽거나 출력하지 않는다.
- 파일·diff·검색 결과·검사 명령을 근거로 기록한다.
- PR·Issue·커밋은 변경 이력이지 현재 정본이 아니다.
- “영향 없음”은 전수 보장이 아니며 확인한 대상과 근거를 기록한다.
- 정본끼리 충돌하거나 필요한 대상을 읽지 못하면 통과로 표시하지 않는다.

## 변경 기준 확인

1. 사용자가 기준을 지정하면 그 기준을 사용한다. 예: PR, 커밋, 브랜치 비교, 특정 파일.
2. 기준이 없으면 현재 작업 트리의 staged·unstaged diff와 관련 untracked 파일을 확인한다.
3. 변경 기준이 없으면 임의로 최근 커밋을 검사하지 말고 검사 대상이 없다고 보고한다.
4. `git status --short --branch`와 diff를 확인하되 보호 파일의 내용은 열지 않는다.

## 검사 절차

### 1. 변경 유형과 정본 확인

`docs/harness/change-impact-map.md`의 변경 유형을 하나 이상 선택한다.

- `product`: 기능 행동, 사용자 역할, 정책, 성공 조건
- `api`: HTTP 경로, 요청·응답, 상태 코드, 계약 문서
- `data`: 엔티티, 스키마, 저장·조회 규칙, 마이그레이션
- `architecture`: 컴포넌트 경계, 의존성, 실행 흐름, 결정
- `security`: 인증·인가, 개인정보, 비밀값, 외부 쓰기, 보호 규칙
- `harness`: 지침, skill, 검증 명령, CI, 회귀 기준

선택한 행의 `canonical_sources`를 먼저 읽고 변경의 현재 의미를 정본에서 확정한다.
복수 유형이면 영향 집합을 합친다.

### 2. 영향 집합 확정

`candidate_impacts`를 출발점으로 feature ID, API 경로, 도메인명, 클래스명, 문서 제목,
결정 ID와 핵심 용어를 저장소에서 검색한다. 검색 결과만으로 영향 대상이라고 단정하지
말고 실제 의미와 참조 관계를 확인한다.

다음 대상을 구분해서 기록한다.

- 변경한 대상: 실제 내용이 갱신된 문서·코드·테스트
- 확인했지만 변경 없음: 비교 결과 현재 내용이 유효한 대상
- 확인하지 못함: 접근·시간·환경 제약으로 판단하지 못한 대상
- 미해결: 충돌, 누락, 모호한 요구사항 또는 추가 결정이 필요한 대상

### 3. 정합성 검사

- 정본의 정책·행동·용어가 기능 문서와 사용자 흐름에 일치하는지 확인한다.
- API 변경이면 Controller·DTO·Service·Converter, API 문서, Swagger/OpenAPI와 Postman
  자료가 같은 경로·필드·상태 코드를 설명하는지 확인한다.
- 데이터 변경이면 도메인 모델·저장 구조·마이그레이션·조회 코드·테스트의 이름과 규칙을 비교한다.
- 아키텍처 변경이면 결정 문서·구조 문서·패키지 의존성·실제 코드 흐름을 비교한다.
- 보안 변경이면 보호 경로, 인증·인가 흐름, 로그와 테스트에 비밀값·개인정보 노출이 없는지 확인한다.
- 하네스 변경이면 관련 지침·skill·검증기·회귀 테스트·문서 링크가 서로 연결되는지 확인한다.
- 링크·anchor·구조 검사는 가능한 명령으로 실행하고 의미 판단은 읽은 근거와 함께 표시한다.

### 4. 검증 실행

변경 범위에 맞는 안전한 읽기·검증 명령만 실행한다.

1. 관련 문서 링크·구조 검사
2. 관련 단위·계약·아키텍처 테스트
3. 필요한 경우 프로젝트의 검증 절차

검사를 실행하지 못하면 명령과 이유를 기록한다. 실행하지 않은 검사를 통과로 간주하지 않는다.

## 결과 형식

다음 형식을 유지해 짧고 근거 중심으로 보고한다.

```markdown
# 변경 영향 검사

## 결과 요약
- 검사 기준:
- 변경 유형:
- 최종 판정: `통과` / `수정 필요` / `검증하지 못함` / `의미 검토 필요`

## 정본과 영향 집합
- 주요 정본:
- 영향 대상:

## 변경한 대상
-

## 확인했지만 변경 없음
- 대상 — 판단 근거

## 확인하지 못함
- 대상 — 이유

## 불일치·미해결
- 문제 — 근거 — 필요한 조치

## 검증 근거
- 명령 또는 파일:
- 결과:

## 다음 조치
-
```

검사 결과에 없는 대상은 확인한 것으로 기록하지 않는다. 사용자가 수정을 요청하지 않은
동안에는 파일을 변경하지 않고, 수정이 필요하면 대상·이유·수정 범위를 먼저 보고한다.
