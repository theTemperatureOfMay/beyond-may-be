# 구현 계획 작성

## 1. 설계 문서 확인

1. 저장소의 `AGENTS.md`를 읽고 적용하라.
2. 사용자가 지정한 설계 문서 또는 대화에서 방금 승인된 설계 문서를 찾으라.
3. 설계 문서가 있으면 상태와 내용을 확인하라.

설계 문서가 없다면 다음 형식으로 질문하라.

> 설계 문서가 필요합니다. `design-spec` 스킬을 실행하시겠습니까?

- 승인하면 계획을 만들지 말고 `design-spec` 실행으로 넘겨라.
- 거절하면 대화 문맥을 기준으로 계획을 작성하고 문서에 `설계 문서 없이 작성됨`이라고 표시하라.

## 2. 실제 구현 환경 조사

- 설계 문서를 기준으로 실제 파일, 코드, 테스트 구조, 빌드 설정, 관련 문서를 확인하라.
- 파일과 명령 이름을 추측하지 말고 저장소에서 확인하라.
- 프로젝트 문서와 실제 코드가 다르면 차이를 기록하고 계획 준비 상태를 판단할 때 반영하라.

계획 문서를 작성하기 전에 다음 내용을 실제 저장소 기준으로 판단할 수 있는지 확인하라.

1. 구현할 설계 결정과 완료 조건
2. 수정하거나 만들 파일과 각 파일의 책임
3. 구현 순서, 선행 작업과 단계 간 의존성
4. TDD 적용 여부와 실패하는 첫 검증
5. 관련 테스트, 품질 검사와 빌드 명령
6. 마이그레이션, 외부 작업, 위험 작업과 필요한 승인 시점

- 저장소에서 확인할 수 없는 정보가 구현 결과나 순서를 크게 바꾸면 `clarify-intent`
  스킬을 실행하라.
- `clarify-intent`에 승인된 설계의 고정 조건, 저장소에서 확인한 사실과 구현에 영향을
  주는 미해결 사항을 전달하라.
- 승인된 설계 결정을 다시 질문하지 말고 설계 범위 안의 구현 판단만 구체화하라.
- 질문 개수, 추천 선택지와 질문 형식을 이 스킬에서 다시 정의하지 말고
  `clarify-intent`의 절차를 따르라.
- `clarify-intent`가 정리한 제약, 성공 조건, 채택한 가정과 남은 위험을 계획 입력으로
  사용하라.
- 사용자가 판단을 위임해 채택한 권장안은 계획 문서에 기록하라.
- 위 항목을 모두 판단할 수 있을 때만 계획 작성 단계로 이동하라.

## 3. 계획 문서 이름 정하기

설계 문서가 있으면 다음 규칙을 적용하라.

- 설계 문서와 같은 `yymmdd-nn-{작업 내용}`을 사용하라.
- `.dev/plan/yymmdd-nn-{작업 내용}-plan.md`에 저장하라.

설계 문서 없이 계획을 만들면 다음 규칙을 적용하라.

1. Asia/Seoul 기준 오늘 날짜를 `yymmdd`로 구하라.
2. `.dev/specs/`, `.dev/plan/`, `.dev/implementation/`에서 오늘의 가장 큰 작업 번호를 찾으라.
3. 다음 번호를 두 자리로 사용하라. 오늘 문서가 없으면 `01`을 사용하라.

나중에 새 설계를 만들게 되면 설계 없는 기존 계획 번호를 재사용하지 마라. 새 번호의 설계와 계획을 한 쌍으로 만들라.

## 4. 계획 문서 작성

문서 맨 위에 다음 정보를 포함하라.

- 상태: `작성 중`
- 작성 날짜와 시간
- 설계 문서 링크 또는 `설계 문서 없이 작성됨` 표시
- 구현 문서가 있으면 해당 링크

계획 본문에는 다음 내용을 체크박스로 작성하라.

1. 수정하거나 만들 실제 파일
2. 파일별 구현 내용과 순서
3. TDD 적용 여부
4. 작성하거나 실행할 테스트
5. 코드 품질 검사와 빌드 명령
6. 자체 검토 항목
7. 완료 조건

다음 원칙을 지켜라.

- AI가 구현 중 판단할 수 있는 작은 코드 작성 방법까지 고정하지 마라.
- 설계의 중요한 결정과 안전 조건은 구현자가 놓치지 않게 구체적으로 적어라.
- 설명은 한국어로 작성하고 코드와 기술 이름은 원래 영어를 유지하라.
- 변경 이력 목록을 만들지 말고 최신 내용만 유지하라.
- 설계 문서가 있으면 양쪽 문서에 서로의 링크를 추가하라.

## 5. 승인 받기

문서를 저장한 뒤 사용자에게 계획 문서 링크를 보여주고 승인 또는 수정 요청 하나만 질문하라.

- 승인되면 상태를 `승인됨`으로 바꾸고 승인 날짜와 시간을 기록하라.
- 중요한 수정 요청을 받으면 상태를 `작성 중`으로 되돌리고 기존 문서를 수정하라.
- 수정이 끝나면 다시 승인을 요청하라.
- 승인된 뒤 공통 하네스가 `implement`를 실행하도록 넘겨라.
