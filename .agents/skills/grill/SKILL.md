# Grill

Grill은 요구사항·아이디어·계획·결정을 실행 가능한 수준까지 명확히 하는
model-invokable 진입점이다. 사용자가 직접 호출할 수도 있고, 다른 스킬이 같은
명확화 흐름을 재사용할 수도 있다.

이 문서의 전역 절차는 모든 호출에서 읽는다. 내부 절차는 라우팅이 끝난 뒤
선택된 문서만 읽는다.

## 전역 절차

### 1. 사실과 결정을 분리한다

요청, 현재 대화, 저장소 맥락을 읽고 다음을 구분한다.

- 환경·도구·문서에서 확인할 수 있는 사실
- 사용자가 결정해야 하는 선택
- 아직 확인하지 못한 사실과 미해결 결정

환경에서 확인할 수 있는 사실은 도구로 먼저 조사한다. 사실을 사용자에게
확인받기 위해 질문하지 않는다. 확인하지 못한 사실은 추측하지 않고 미해결
항목으로 표시한다.

완료 기준: 현재 요청의 사실·결정·미해결 항목을 각각 구분했다.

### 2. 두 축으로 경로를 선택한다

요청 의도에서 질문 방식과 기록 방식을 독립적으로 판단한다.

| 질문 방식 | 기록 없음 | 기록 필요 |
|---|---|---|
| 1문 1답 | grilling | grill-with-docs |
| batch 라운드 | batch-grill-me | batch-grill-with-docs |

질문 방식은 한 번에 하나의 질문을 답하려는지, 현재 frontier의 여러 질문을
한 라운드에 답하려는지로 판단한다. 기록 방식은 CONTEXT.md·용어집·ADR 또는
합의의 지속 기록을 요청하는지로 판단한다. 저장소가 있다는 사실만으로
기록 필요를 선택하지 않는다.

사용자가 경로, batch, 문서화를 명시하면 자동 판단보다 그 요청을 우선한다.
명시 요청이 없고 어느 축에도 신호가 없으면 grilling을 기본 경로로 제안한다.
신호가 충돌하면 임의로 실행하지 않고 조합안에 충돌을 표시한다.

완료 기준: 네 경로 중 하나와 선택 이유가 결정되었다.

### 3. 조합안을 먼저 승인받는다

실행 전에 다음 조합안을 제시한다.

1. 선택한 경로와 선택 이유
2. 내부 절차와 실행 순서
3. 예상 대화 산출물
4. 예상되는 CONTEXT.md·ADR 기록
5. 알려진 blocker와 미해결 항목

사용자가 조합안을 승인할 때까지 질문 절차, domain-modeling, 문서 기록을
시작하지 않는다. 조합안이 거부되거나 변경되면 실행하지 않은 상태에서
새 조합안을 제시하고 다시 승인받는다.

완료 기준: 사용자가 실행할 조합과 순서를 승인했다.

### 4. 선택된 내부 절차만 실행한다

승인된 경로에 따라 필요한 context pointer만 따른다.

- `grilling`이면 `references/grilling.md`를 읽는다.
- `grill-with-docs`이면 `references/grilling.md`를 읽고 `/domain-modeling`을
  함께 적용한다.
- `batch-grill-me`이면 `references/batch-grill.md`를 읽는다.
- `batch-grill-with-docs`이면 `references/batch-grill.md`를 읽고
  `/domain-modeling`을 함께 적용한다.

문서화 경로에서 확정된 용어와 결정의 기록은 `/domain-modeling`이 소유한다.
`/grill`은 호출 시점과 결과만 조합한다.

내부 절차는 서로를 직접 호출하지 않는다. 실행 중 추가 절차가 필요하면
진행을 멈추고 전역 절차로 돌아와 새 조합안과 승인을 받는다.

완료 기준: 승인된 내부 절차만 실행했고, 추가 절차는 재승인 없이 실행하지 않았다.

### 5. 공유 이해를 확인하고 종합한다

내부 절차가 종료되면 다음을 대화에서 종합한다.

- 승인된 조합과 실제 실행 순서
- 내부 절차별 대화 산출물
- domain-modeling이 만든 기록 또는 기록하지 않은 이유
- 미해결 항목과 다음 선택지

사용자가 종합 결과를 확인해 공유 이해를 확정할 때까지 작업을 완료로 보고하지
않는다. /grill은 별도 세션 결과 파일을 만들지 않는다.

완료 기준: 사용자가 결과를 확인했거나, 공유 이해 대기 상태가 명시되었다.

## 네 가지 라우팅 경로

| 경로 | 내부 절차 | 추가 적용 | 기본 산출물 |
|---|---|---|---|
| grilling | references/grilling.md | 없음 | 대화 합의 요약 |
| grill-with-docs | references/grilling.md | /domain-modeling | 합의 요약과 필요한 CONTEXT.md·ADR |
| batch-grill-me | references/batch-grill.md | 없음 | 설계 트리·라운드 결과·합의 요약 |
| batch-grill-with-docs | references/batch-grill.md | /domain-modeling | batch 산출물과 필요한 CONTEXT.md·ADR |

네 경로는 `/grill`이 조합안을 설명하기 위한 이름이다. 어느 reference도
독립 진입 스킬이 아니다.

## 산출물 책임

- /grill은 라우팅·승인·중단·재승인·최종 대화 메타 요약을 책임진다.
- references/grilling.md는 1문 1답과 대화 합의 요약을 책임진다.
- references/batch-grill.md는 frontier·라운드·설계 트리와 합의 요약을 책임진다.
- /domain-modeling은 용어 경계, CONTEXT.md 갱신과 필요한 ADR을 책임진다.

기록 필요 경로라도 모든 실행에서 ADR을 만들지는 않는다. ADR은
/domain-modeling이 되돌리기 어려움, 맥락 없이 놀라움, 실제 대안 간 trade-off를
모두 확인한 경우에만 다룬다.

## 중단과 오류

- 조합안 승인 전에는 어떠한 내부 절차나 기록도 시작하지 않는다.
- 확인하지 못한 사실은 미해결 항목으로 남기고 추측하지 않는다.
- CONTEXT.md·ADR 충돌이나 기록 실패는 domain-modeling의 결과와 함께 보고하고
  기록 완료로 표현하지 않는다.
- 추가 절차가 필요하면 현재 실행을 중단하고 새 조합안을 승인받는다.
- 최종 결과 확인이 없으면 공유 이해 대기 상태로 남긴다.
