# GitHub 이슈 템플릿 생성

자동 선택으로 템플릿을 읽고 이슈 유형을 분류하며 제목·본문 초안을 작성할 수 있다.
GitHub 이슈 생성은 아래 5단계에서 최종 대상과 최종 내용을 보여 주고 별도 승인받는다.

## 원칙

- 매번 `.github/ISSUE_TEMPLATE/config.yml`과 사용 가능한 모든 `.md` 템플릿을 UTF-8로 읽고 현재 파일을 정본으로 사용한다. 스킬에 템플릿 본문을 복사해 고정하지 않는다.
- `config.yml`의 `blank_issues_enabled: false`를 존중하고 임의의 빈 이슈 양식을 만들지 않는다.
- YAML 앞부분의 `title`, `labels`, `assignees`를 메타데이터로 사용하고, 닫는 `---` 뒤의 Markdown을 본문 원본으로 사용한다.
- 본문을 만들 때 제목과 섹션 순서, `##` 헤딩, HTML 안내 주석, 체크박스, 빈 줄과 모든 이모지를 그대로 유지한다. 안내 주석도 삭제하지 않는다.

## 템플릿 선택

각 `.md` 템플릿의 YAML `name`과 `about`을 읽어 사용자 요청에 가장 맞는 템플릿을 선택한다.
파일 이름, 제목 접두사, 라벨, 담당자와 본문 구조는 현재 파일에서 가져오고 스킬에 목록으로
복제하지 않는다.

둘 이상의 템플릿이 같은 정도로 맞으면 현재 템플릿의 `name`과 `about`을 선택지로 보여 주고
하나만 질문한다.

## 생성 절차

1. 대상 저장소와 이슈 유형을 확인한다. 사용자가 초안만 요청했으면 생성하지 않고 제목과 본문만 작성한다.
2. 선택한 템플릿 파일을 다시 읽어 현재 내용과 메타데이터를 확인한다. 템플릿의 이모지를 직접 재입력하지 말고 읽은 본문에서 복사한다.
3. 사용자가 제공한 정보만 해당 안내 주석 아래, 체크박스 또는 빈 항목에 채운다. 정보가 없으면 사실을 지어내지 말고 필요한 항목을 질문한다.
4. 제목은 템플릿의 접두사를 그대로 앞에 두고 짧은 한국어 요약을 덧붙인다. 템플릿에 없는 라벨·담당자·섹션·이모지를 추가하지 않는다.
5. 생성 직전에 저장소, 제목, 라벨, 담당자와 최종 Markdown 본문을 사용자에게 보여 주고 명시적으로 확인받는다.
6. 확인 후 사용 가능한 GitHub 연동 도구로 이슈를 생성한다. 연동 도구가 없으면 인증된 `gh issue create`를 사용하되 최종 본문을 그대로 전달하고, 템플릿 파일 이름만 넘겨 대화형 편집을 다시 시작하지 않는다.
7. 생성된 이슈 URL과 번호를 확인하고, 템플릿의 모든 헤딩·이모지·체크박스가 최종 본문에 남았는지 검증한다.

## 외부 작업 안전

외부 쓰기 권한, 인증 또는 대상 저장소가 불명확하면 생성하지 말고 그 사실만 보고한다. 비밀번호, 토큰과 개인정보를 본문·로그에 기록하지 않는다.
