# 승인된 계획 구현

## 1. 구현 시작 조건 확인

1. 저장소의 `AGENTS.md`를 읽고 적용하라.
2. 사용자가 지정한 계획 문서를 끝까지 읽으라.
3. 연결된 설계 문서가 있으면 끝까지 읽으라.
4. 계획 상태가 `승인됨`인지 확인하라.
5. 사용자가 현재 대화에서 특정 계획을 가리키며 구현을 명확히 요청했다면 그 요청을 승인으로 인정하고 계획에 승인 상태와 시간을 반영하라.
6. 승인된 계획이 없으면 구현하지 말고 계획 승인을 요청하라.

## 2. TDD 적용 여부 알리기

- 테스트가 필요한 코드 작업이면 구현 전에 `TDD 방식으로 구현하겠습니다.`라고 알리라.
- 문서나 단순 설정처럼 TDD가 필요 없는 작업이면 구현 전에 `TDD 제외 작업입니다.`라고 알리라.
- TDD 대상은 `실패하는 테스트 → 통과하는 최소 코드 → 코드 정리` 순서로 구현하라.

## 3. 계획 실행

- 계획의 체크박스 순서대로 작업하라.
- 각 단계가 끝날 때마다 계획 문서의 체크박스를 즉시 갱신하라.
- 구체적인 코드 작성 방법은 설계와 계획의 경계 안에서 자유롭게 선택하라.
- 하네스와 관계없는 사용자의 기존 변경을 수정하거나 되돌리지 마라.
- 새 라이브러리가 승인된 계획에 포함되어 있으면 추가 질문 없이 설치하라.

## 4. 계획과 달라진 경우

변수 이름이나 작은 코드 위치처럼 결과와 방법이 같은 차이는 스스로 처리하라.

중요한 구현 방법이 계획과 달라지면 즉시 구현을 멈추고 다음과 같이 질문하라.

> 현재 구현 방법이 승인된 계획과 달라집니다. 계획 문서를 업데이트할까요?

- 승인하면 계획 상태를 `작성 중`으로 바꾸고 계획을 수정한 뒤 재승인을 요청하라.
- 재승인되면 구현을 계속하라.
- 계획 수정을 거절하면 계획 문서를 바꾸지 않고 사용자가 요청한 구현을 계속하라.
- 추가 요청이 승인된 설계의 목적이나 구조를 바꾸면 구현을 멈추고 설계 문서 수정으로 돌아가라.
- 어느 쪽인지 분명하지 않으면 한 번에 하나씩 질문하라.

## 5. 안전하게 실행하기

- 데이터 삭제처럼 되돌리기 어려운 작업은 계획에 포함되어 있어도 실행 직전에 다시 확인하라.
- Git으로 되돌릴 수 있는 코드 파일 삭제는 승인된 계획에 있으면 다시 묻지 마라.
- 커밋, 브랜치 생성·변경, push, Pull Request 생성은 사용자가 별도로 요청하지 않으면 실행하지 마라.
- 비밀번호, API 키, 접근 토큰, 개인정보를 문서나 로그에 기록하지 마라.

## 6. 검증하기

구현을 마친 뒤 다음 순서로 검증하라.

1. 전체 테스트를 실행하라.
2. 프로젝트에 등록된 코드 품질 검사를 실행하라.
3. 전체 빌드를 실행하라.
4. 변경한 코드를 다시 읽고 설계, 계획, 사용자 요청과 비교하라.

Java와 Gradle 프로젝트에서는 저장소에 다른 명령이 적혀 있지 않다면 다음 명령을 사용하라.

- Windows: `gradlew.bat test`, `gradlew.bat spotlessCheck`, `gradlew.bat build`
- macOS/Linux: `./gradlew test`, `./gradlew spotlessCheck`, `./gradlew build`

- 이번 변경 때문에 검사가 실패하면 스스로 수정하고 다시 실행하라.
- 기존 문제로 실패하면 이번 변경과 구분해 보고하라.
- 환경 문제로 검사를 실행하지 못하면 코드 작업 완료 여부와 검증 실패 사유를 나누어 설명하라.

## 7. 구현 문서 작성

구현이 끝나거나 더 진행할 수 없게 되면 반드시 구현 문서를 작성하라.

1. 계획 파일 이름의 `-plan.md`를 `-implementation.md`로 바꾸라.
2. `.dev/implementation/`에 저장하라.
3. 설계·계획·구현 문서가 서로 링크되게 갱신하라.

구현 문서에 다음 내용을 포함하라.

- 상태: `구현 완료` 또는 `구현 실패`
- 구현 날짜와 시간
- 연결된 설계와 계획 문서
- 실제 구현 내용
- 변경한 파일
- 실행한 테스트와 결과
- 코드 품질 검사 결과
- 빌드 결과
- 자체 검토 결과
- 남은 문제

구현이 완료되면 계획의 모든 완료된 체크박스를 갱신하고 계획 상태를 `구현 완료`로 바꾸라. 실패하거나 중단되면 완료한 체크박스만 표시하고 계획 상태를 `구현 실패`로 바꾸라.
