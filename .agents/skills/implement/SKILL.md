# 승인된 계획 구현

## 1. 시작 조건

1. `AGENTS.md`와 지정된 계획을 끝까지 읽는다.
2. 연결된 설계 문서가 있으면 함께 읽는다.
3. 계획 상태가 `승인됨`인지 확인한다. 사용자가 현재 대화에서 특정 계획 구현을
   명확히 요청했다면 그 요청을 승인으로 기록한다.
4. 승인된 계획이 없으면 구현하지 않고 승인을 요청한다.

승인된 일반 구현 계획과 큰 작업 계획은 모두 입력이다. 작은 작업은 공통 하네스의
직접 구현 절차를 따른다.

## 2. 구현

- 테스트가 필요한 코드는 TDD 방식임을 알리고
  `실패하는 테스트 → 통과하는 최소 코드 → 코드 정리` 순서로 구현한다.
- 문서와 단순 설정은 TDD 제외 작업임을 알리고 필요한 검증만 수행한다.
- 계획 체크박스 순서대로 작업하고 완료할 때마다 즉시 갱신한다.
- 하네스와 관계없는 사용자 변경은 수정하거나 되돌리지 않는다.
- 계획 범위의 작은 구현 차이는 처리하되 목적·구조·공개 계약·완료 조건이 달라지면
  중단하고 계획 수정과 재승인을 요청한다.

## 3. 안전

- 데이터 삭제처럼 되돌리기 어려운 작업은 실행 직전에 다시 확인한다.
- 승인된 계획에 포함된 Git으로 복구 가능한 코드 파일 삭제는 다시 묻지 않는다.
- 커밋, 브랜치 생성·변경, push와 Pull Request는 사용자가 별도로 요청한 경우에만
  수행한다.
- 비밀번호, API 키, 접근 토큰과 개인정보를 코드·문서·로그에 기록하지 않는다.

## 4. 검증

구현 후 다음 순서로 검증한다.

1. 전체 테스트
2. 코드 품질 검사
3. 전체 빌드
4. 변경 코드와 diff를 계획·사용자 요청에 대조

Windows Gradle 프로젝트의 기본 명령은 `gradlew.bat test`,
`gradlew.bat spotlessCheck`, `gradlew.bat build`다. 이번 변경 때문에 실패한
검사는 수정하고, 기존 실패와 환경 문제는 구분해 보고한다.

## 5. 완료 기록

계획 이름의 `-plan.md`를 `-implementation.md`로 바꾼 구현 문서를
`.dev/implementation/`에 작성하고 설계·계획과 상호 링크한다. 구현 문서에는 실제
변경 파일, 계획과의 차이, 테스트·품질·빌드·자체 검토 결과와 남은 문제를 기록한다.

완료하면 계획 체크박스와 상태를 `구현 완료`로 갱신한다. 중단되면 완료 항목만
표시하고 `구현 실패`와 이유를 기록한다.
