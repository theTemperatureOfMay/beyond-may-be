# CONTEXT.md 형식

## 구조

```md
# {컨텍스트 이름}

{이 컨텍스트가 무엇이며 왜 존재하는지 한두 문장으로 설명한다.}

## 용어

**주문**:
{이 용어를 한두 문장으로 설명한다.}
_피하기_: 구매, 거래

**청구서**:
배송 후 고객에게 결제를 요청하는 문서.
_피하기_: 계산서, 결제 요청서

**고객**:
주문하는 개인 또는 조직.
_피하기_: 클라이언트, 구매자, 계정
```

## 규칙

- **의견을 분명히 한다.** 같은 개념에 여러 단어가 있으면 가장 적절한 하나를 선택하고 나머지는 `_피하기_` 아래에 적는다.
- **정의를 간결하게 유지한다.** 최대 한두 문장으로 작성한다. 무엇을 하는지가 아니라 무엇인지 정의한다.
- **이 프로젝트의 컨텍스트에만 해당하는 용어만 포함한다.** 타임아웃, 오류 유형, 유틸리티 패턴처럼 일반적인 프로그래밍 개념은 프로젝트에서 광범위하게 사용하더라도 포함하지 않는다. 용어를 추가하기 전에 "이것은 이 컨텍스트에 고유한 개념인가, 아니면 일반적인 프로그래밍 개념인가?"라고 묻는다. 전자일 때만 포함한다.
- **자연스럽게 묶이는 용어는 소제목 아래 그룹화한다.** 모든 용어가 하나의 일관된 영역에 속한다면 평면 목록을 사용해도 된다.

## 단일 컨텍스트와 여러 컨텍스트 저장소

**단일 컨텍스트(대부분의 저장소):** 저장소 루트에 `CONTEXT.md` 하나를 둔다.

**여러 컨텍스트:** 저장소 루트의 `CONTEXT-MAP.md`가 컨텍스트의 위치와 서로의 관계를 설명한다.

```md
# 컨텍스트 맵

## 컨텍스트

- [주문](./src/ordering/CONTEXT.md) — 고객 주문을 접수하고 추적한다
- [청구](./src/billing/CONTEXT.md) — 청구서를 생성하고 결제를 처리한다
- [이행](./src/fulfillment/CONTEXT.md) — 창고 피킹과 배송을 관리한다

## 관계

- **주문 — 이행**: 주문은 `OrderPlaced` 이벤트를 발행하고, 이행은 이를 받아 피킹을 시작한다.
- **이행 — 청구**: 이행은 `ShipmentDispatched` 이벤트를 발행하고, 청구는 이를 받아 청구서를 생성한다.
- **주문 — 청구**: `CustomerId`와 `Money`를 공유하는 타입이 있다.
```

스킬은 다음 기준으로 적용할 구조를 판단한다.

- `CONTEXT-MAP.md`가 있으면 이를 읽고 컨텍스트를 찾는다.
- 루트에 `CONTEXT.md`만 있으면 단일 컨텍스트로 본다.
- 둘 다 없으면 첫 번째 용어가 확정될 때 루트에 `CONTEXT.md`를 지연 생성한다.

여러 컨텍스트가 있으면 현재 주제가 어느 컨텍스트에 해당하는지 판단한다. 분명하지 않으면 사용자에게 묻는다.
