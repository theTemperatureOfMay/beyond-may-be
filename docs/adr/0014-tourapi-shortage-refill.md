# ADR-0014 부족한 추천 유형만 TourAPI 변경분으로 보충한다

추천 생성 시 최초 유형별 할당량보다 활성 DB 장소가 적으면 기존 광주 스냅샷만으로
사용자 성향 비율을 맞출 수 없다. 초기 수집 API를 반복 호출하면 같은 스냅샷을 다시
받으므로, 부족한 요청에 한해 변경분을 조회할 경계가 필요하다.

### 결정

- 런타임 장소 정본은 계속 PostgreSQL `places`다.
- 추천 생성 요청에서 하나 이상의 유형이 최초 할당량보다 부족할 때만
  `KorService2/areaBasedSyncList2`를 최대 한 번 호출한다.
- 광주 `areaCode=5`와 현재 법정동 권역 `lDongRegnCd=12`, 노출 장소 `showflag=1`,
  2026-08-21 이후 변경분의 첫 페이지를 최대 200건 조회하며 추가 페이지와 자동
  재시도는 사용하지 않는다.
- `NA`, `FD`, `VE`, `HS`를 각각 `THINKER`, `FOODIE`, `ARTIST`, `REMEMBERER`로
  연결한다. `AC`, `EV`, `EX`, `LS`, `SH`와 숙박은 제외한다.
- 필수값을 갖춘 신규 장소를 `places`에 먼저 저장한 뒤 같은 요청의 후보로 사용한다.
  기존 `tour_content_id`는 수정하지 않고 DB 유일 제약 충돌은 무시한다.
- 외부 실패나 유효한 신규 장소가 없으면 기존 DB 후보와 규칙 기반 재배분으로 계속한다.
- 연결·응답 timeout은 각각 최대 5초이며 외부 키는 설정으로만 주입하고 로그에 남기지
  않는다.
- 외부 조회 중에는 DB 트랜잭션과 사용자 행 잠금을 유지하지 않는다. 응답을 받은 뒤
  사용자 잠금을 다시 획득하고 신규 저장·후보 재조회·AI 후보 준비를 짧은 트랜잭션에서
  처리한다. 이후 Groq 선별과 추천 세트 저장 경계는
  [ADR-0015](0015-groq-recommendation-ranking.md)를 따른다.

### 검토한 대안

- `areaBasedList2`를 다시 호출하는 방식은 초기 200건을 반복하므로 사용하지 않는다.
- 유형별로 외부 API를 여러 번 호출하거나 200건 이후 페이지를 조회하는 방식은 추천
  요청의 지연과 호출 수를 늘리므로 MVP에서 사용하지 않는다.
- 외부 응답을 바로 추천하는 방식은 DB 정본과 ID 검증 원칙을 깨므로 사용하지 않는다.

### 영향

- ADR-0003의 “한국관광공사 OpenAPI는 초기 광주 장소 수집에만 사용한다”는 제한만
  이 ADR이 대체한다. DB 정본, AI의 DB 장소 선별과 검수 원칙은 유지한다.
- 추천 서비스는 부족 여부를 먼저 계산하고, 신규 저장을 시도한 경우 활성 후보를 다시
  조회한다.
- 외부 장애는 추천 생성 실패가 아니며, 저장된 후보 수에 따라 20곳 미만 또는 빈 목록도
  정상 응답이다.

### 영향 대상

- 변경 유형: `product`, `data`, `architecture`, `security`
- 변경한 대상: ADR-0003의 부분 대체 관계, 장소 선택·OpenAPI 적용·사용자 흐름·MVP
  정본, 백엔드 아키텍처, 추천 생성 OpenAPI 설명과 Postman 자료, TourAPI 설정·클라이언트,
  신규 장소 저장·추천 서비스와 테스트, TourAPI 운영 키의 SSM·IAM·ECS 주입 구성과
  배포 문서
- 확인했지만 변경하지 않음: 추천 HTTP 경로·요청·응답·상태 코드, `Place` 스키마와 V7·V8
  migration, AI의 DB 장소 선별 원칙, 추가 추천 회차, 주기적 전체 동기화, `CONTEXT.md`,
  4.4.1 주변 장소 런타임 호출 결정
- 확인하지 못함: 실제 TourAPI 운영 응답, Terraform CLI 검증과 운영 ECS의 비밀값 주입 상태
- 미해결: 추가 추천 회차는 후속 티켓 범위다. 추천 AI 선별은 ADR-0015에서,
  상세정보 사후 보강은 ADR-0016에서 후속 해결했다.
  4.4.1 `locationBasedList2`와 ADR-0003의 관계는 이 ADR이 대체하지 않으며 제품 논의
  필요 문서에서 별도로 추적한다.

### 변경 영향 검사

- 검사 스킬: `change-impact-review`
- 검사 일자: 2026-08-21
- 검사 결과: `통과` (추천 부족분 보충 범위)
- 검사 근거: ADR-0003의 부분 대체 관계, 제품·OpenAPI·Postman·MVP·아키텍처 정본과
  구현·테스트를 대조했다. 전체 89개 테스트, Spotless, build, 제품 지식 베이스·하네스
  semantic 검사, Postman JSON 파싱과 `git diff --check`가 통과했다. 4.4.1 주변 장소
  호출의 기존 미해결 결정은 이 ADR의 대체 범위에서 제외해 별도로 추적한다. 실제
  TourAPI와 운영 비밀값은 호출하거나 읽지 않았다. 상세정보 사후 보강의 후속 해결
  상태는 ADR-0016과 대조했다.
