# ADR-0028 방문 인증 후 사진과 메모를 별도 기록으로 저장한다

방문 인증은 위치 검증과 지도 진행률을 확정하고, 방문 기록 작성은 그 인증 이력에 사진과
메모를 남긴다. 기록 작성을 건너뛰어도 인증은 유지된다. 마지막 장소 인증은 탐험을 자동
완료하므로 기록 저장을 진행 중 탐험으로 제한하면 마지막 장소의 기록을 남길 수 없다.

## 결정

- [ADR-0027](0027-private-s3-visit-photo-storage.md)의 사진 전용 API·무제한 장수·메모 없음·완료 후 첨부 금지 계약을 대체한다.
- 기존 `/photos` API를 `POST /api/v1/visits/{visitId}/record`로 바꾸고 사진과 메모를 한 요청으로 저장한다. 상세 입력·응답·제한은 [기능 5.2.1](../product/features/travel-records.md#521-방문한-장소-목록-조회)을 따른다.
- 작성자 확인은 유지하고 ACTIVE 또는 COMPLETED 참여자의 기록 저장을 허용한다. LEFT 참여자는 저장할 수 없다. 팀 전체 조회 권한은 현재·과거 참여자로 유지한다.
- Visit에 nullable 메모를 추가하고 사진은 기존 VisitPhoto·비공개 S3 저장 방식을 재사용한다. 별도 기록 테이블이나 인증 상태를 추가하지 않는다.
- 여러 사진과 메모의 DB 변경은 한 트랜잭션이다. 실패하면 이번 요청의 업로드 객체만 최선 노력으로 삭제하고 기존 인증·기록은 보존한다.
- ADR-0027의 비공개 S3·Task Role·HTTPS·암호화·서명 URL·표시 순서 잠금·실패 보상 정책은 유지한다. Visit 인증 응답과 실시간 이벤트는 변경하지 않는다.

## 대안과 영향

- 인증 API에 사진·메모를 합치면 사진 업로드 실패가 인증까지 막으므로 분리한다.
- 사진 업로드마다 메모를 따로 저장하면 한 화면의 저장이 부분 성공할 수 있어 한 요청으로 받는다.
- 변경 대상: 방문 Controller·DTO·Service·Converter·Visit, Flyway V10, multipart 요청 크기, 서비스·HTTP·DB 테스트, 기능 명세·MVP·사용자 흐름·아키텍처·논의 필요·Postman·용어집.
- 확인 대상: 방문 인증·STOMP 이벤트, S3 저장소·IAM, 안전 정책·하네스·스킬. 기존 구조와 권한 경계에 이 변경을 적용하며 새 의존성이나 운영 권한은 추가하지 않는다.
- 복구: 이전 코드로 롤백해도 nullable 메모 열과 기존 사진을 보존한다. 배포 시 V10 적용 후 새 API를 사용하는 클라이언트로 전환해야 한다.
- 미확인: 실제 프런트엔드 화면 연결, 운영 S3·배포 환경. 로컬 Docker 무응답으로 PostgreSQL migration·트랜잭션·동시성 통합 테스트는 실행 완료하지 못했다. 운영 배포는 이번 작업에 포함하지 않는다.
- 검사 근거: `change-impact-review`로 관련 정본·API·Postman·ClueDoc·안전 정책·스킬을 대조했고 제품 지식·하네스 semantic 검사를 통과했다. `code-review`의 두 축에서 발견한 잠금 전 Visit 캐시 문제는 ID projection으로 수정 후 재검토했다. Docker 의존 8개 클래스를 제외한 459개 테스트가 통과했으며 미실행 DB 검증은 후속 확인이 필요하다.
