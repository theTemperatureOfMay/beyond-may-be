# ADR-0005 Visit을 방문과 여행 기록의 정본으로 사용한다

팀 지도 진행 상태, 개인 방문 기록과 밝힌 지도는 모두 참여자의 장소 방문에서
파생된다. 방문 인증에는 위치 검증과 선택적 사진이 필요하지만 원본 위치와 사진
파일을 모두 관계형 DB에 보존할 필요는 없다.

### 배경

팀 지도 진행 상태, 개인 방문 기록과 밝힌 지도는 모두 참여자의 장소 방문에서
파생된다. 방문 인증에는 위치 검증과 선택적 사진이 필요하지만 원본 위치와 사진
파일을 모두 관계형 DB에 보존할 필요는 없다.

### 결정

- `Visit`을 Participant별 CoursePlace 방문의 정본으로 사용한다.
- 같은 Participant의 동일 CoursePlace 중복 Visit을 허용하지 않는다.
- 서버는 요청 GPS로 거리를 재검증하지만 원본 GPS 좌표는 저장하지 않는다.
- 사진 원본은 객체 저장소에 두고 DB에는 비공개 object key와 표시 순서만 저장한다.
- 여행 기록과 밝힌 지도는 Course, Exploration, Participant, Visit과 VisitPhoto를
  조합한 조회 결과로 제공하며 별도 TravelLog 쓰기 모델을 두지 않는다.

### 검토한 대안

- 별도 TravelLog 쓰기 모델을 유지하는 방식의 당시 비교 근거는 기록되지 않았다.
- 원본 GPS 좌표를 보존하는 방식은 사용하지 않는다.

### 영향

- 팀·개인 진행 상태와 여행 기록이 같은 Visit 데이터에서 계산된다.
- 사진 업로드와 Visit 생성의 실패 경계를 분리해야 한다.
- 객체 업로드 후 DB 저장이 실패하면 객체 삭제를 시도하고 남은 고아 객체를 운영
  정리 대상으로 처리해야 한다.
