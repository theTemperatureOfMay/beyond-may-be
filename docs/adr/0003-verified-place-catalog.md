# ADR-0003 검수된 장소 DB를 런타임 정본으로 사용한다

AI 장소 추천, 장소 상세, 코스 생성과 탐험 중 주변 추천은 동일하고 검수된 장소
정보를 사용해야 한다. 지도 경로 계산과 초기 장소 수집은 서로 다른 외부 시스템의
책임이다.

### 배경

AI 장소 추천, 장소 상세, 코스 생성과 탐험 중 주변 추천은 동일하고 검수된 장소
정보를 사용해야 한다. 지도 경로 계산과 초기 장소 수집은 서로 다른 외부 시스템의
책임이다.

### 결정

- 런타임 장소 정본은 PostgreSQL의 `places`다.
- AI는 DB에 존재하는 장소를 선별하며 신규 장소나 임의 ID를 생성하지 않는다.
- 한국관광공사 OpenAPI는 초기 광주 장소 수집에만 사용한다.
- Kakao Maps API를 통한 지도·경로·거리·이동시간 계산은 프런트엔드가 담당하며
  백엔드는 폴리라인과 계산 결과를 저장하지 않는다.
- 5·18 관련 정보는 AI 생성 문구가 아니라 검수된 장소 설명에 포함한다.

### 검토한 대안

- AI가 런타임에 새로운 장소를 생성하는 방식은 사용하지 않는다.
- 외부 장소 제공자를 런타임 정본으로 사용하는 방식의 비교 근거는 기록되지 않았다.

### 영향

- 추천과 코스에 사용하는 모든 장소 ID는 서버 DB 존재 여부를 검증해야 한다.
- 장소 수집과 검수 절차가 런타임 요청 처리와 분리된다.
- 경로 API가 실패해도 텍스트 코스 목록으로 대체할 수 있지만 서버가 경로 결과를
  복구해 주지는 않는다.
