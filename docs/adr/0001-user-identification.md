# ADR-0001 닉네임·식별코드와 서버 세션으로 사용자를 식별한다

서비스는 별도의 이메일이나 소셜 계정 가입 없이 성향 검사를 마친 사용자가 닉네임을
등록하고 이후 같은 사용 상태로 돌아올 수 있어야 한다. 같은 닉네임은 여러 사용자가
사용할 수 있다.

### 배경

서비스는 별도의 이메일이나 소셜 계정 가입 없이 성향 검사를 마친 사용자가 닉네임을
등록하고 이후 같은 사용 상태로 돌아올 수 있어야 한다. 같은 닉네임은 여러 사용자가
사용할 수 있다.

### 결정

- 내부 식별자는 `User.userId`를 사용한다.
- 사용자가 입력하는 닉네임과 서버가 발급하는 공개 식별코드의 조합으로 간편 로그인을
  제공한다.
- 로그인 상태는 원문 토큰을 저장하지 않는 `UserSession`으로 관리한다.
- 식별코드는 강한 인증 수단으로 간주하지 않으며 로그인 시도 횟수를 제한한다.

### 검토한 대안

이메일, 비밀번호 또는 소셜 로그인 도입 여부와 당시 비교 근거는 기록되지 않았다.

### 영향

- 신규 사용자는 별도 계정 공급자 없이 바로 서비스를 시작할 수 있다.
- 식별코드를 분실하면 계정을 복구할 수 없으므로 발급 시 보관 안내가 필요하다.
- 닉네임만으로 사용자를 식별하거나 인증 성공·실패 이유를 구분해서 노출하면 안 된다.
