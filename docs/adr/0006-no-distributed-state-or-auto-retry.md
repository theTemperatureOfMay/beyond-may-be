# ADR-0006 MVP에서 분산 상태와 자동 재시도를 도입하지 않는다

공모전 MVP에는 AI 추천·코스 생성처럼 오래 걸리거나 중복 호출 비용이 있는 요청이
있다. 현재 서버 상태는 PostgreSQL과 프런트엔드 로컬 상태로 관리할 수 있다.

### 배경

공모전 MVP에는 AI 추천·코스 생성처럼 오래 걸리거나 중복 호출 비용이 있는 요청이
있다. 현재 서버 상태는 PostgreSQL과 프런트엔드 로컬 상태로 관리할 수 있다.

### 결정

- MVP에서 Redis를 사용하지 않는다.
- AI 요청의 서버 영속 멱등성 키를 저장하지 않는다.
- API와 AI 요청을 자동 재시도하지 않는다. 요청 중에는 프런트엔드가 전송 버튼을
  비활성화하고, 실패하면 사용자가 해당 요청만 다시 시도한다.

### 검토한 대안

- Redis를 이용한 분산 상태·캐시·rate limit의 구체적인 비교 근거는 기록되지 않았다.
- 서버 영속 멱등성 키와 자동 재시도는 MVP 범위에서 채택하지 않았다.

### 영향

- 네트워크 중복 요청을 완전히 방지하지 못한다.
- 서버가 여러 인스턴스로 확장될 때 WebSocket 상태와 rate limit 전략을 다시 결정해야
  할 수 있다.
- 재시도 UI는 실패한 요청만 다시 호출하고 사용자의 기존 입력을 유지해야 한다.
