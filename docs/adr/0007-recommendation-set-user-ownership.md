# ADR-0007 추천 작업 상태는 User 소유이며 인증 구현과 분리한다

추천 결과는 사용자가 재접속하거나 다시 인증한 뒤에도 이어서 사용할 수 있는 업무
상태다. 인증 토큰이나 로그인 세션은 만료·교체될 수 있으므로 추천 결과의 소유자와
인증 상태를 같은 데이터 관계로 두면 사용자 상태 복구가 인증 수명에 종속된다.

### 배경

추천 결과는 사용자가 재접속하거나 다시 인증한 뒤에도 이어서 사용할 수 있는 업무
상태다. 인증 토큰이나 로그인 세션은 만료·교체될 수 있으므로 추천 결과의 소유자와
인증 상태를 같은 데이터 관계로 두면 사용자 상태 복구가 인증 수명에 종속된다.

### 결정

- 현재 추천 세트의 소유자는 `User`다.
- `RecommendationSet.user_id`는 유일하며 사용자마다 현재 추천 세트 하나만 둔다.
- access token, refresh token, 서버 세션 등 구체적인 인증 방식과 저장소는 별도
  인증 설계에서 결정한다.
- 업무 API는 서버가 확인한 현재 `User` 컨텍스트를 사용하며, body나 query의
  사용자·세션 ID만으로 소유자를 결정하지 않는다.

### 검토한 대안

- `UserSession`에 추천 세트를 연결하는 방식은 인증 세션 만료·교체 시 업무 상태
  복구가 끊길 수 있어 채택하지 않는다.
- 여러 추천 작업을 동시에 보존하는 별도 작업 공간은 현재 명세의 사용자별 현재
  추천 세트 하나 요구에 포함되지 않아 도입하지 않는다.

### 영향

- 사용자가 재인증하거나 기기를 바꿔도 같은 사용자의 현재 추천 세트를 조회할 수
  있다.
- 인증 담당 팀이 토큰 또는 세션 저장 방식을 추가해도 추천 세트의 소유 관계는
  바뀌지 않는다.
- 기능명세의 `세션 ID` 문구는 유지하되 실제 전달 방식은 인증·API 계약에서
  확정한다.
