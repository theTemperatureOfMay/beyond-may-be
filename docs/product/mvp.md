# Beyond May Be 백엔드 MVP 상태

이 문서는 [상세 기능 명세](feature-spec.md)의 모든 소기능에 대해 이 백엔드 저장소가
담당하는 책임과 현재 구현 상태를 관리한다. 프런트엔드 구현 상태나 전체 서비스의
통합 완료 여부는 판단하지 않는다.

- 기준 일자: 2026-07-29
- 제품 범위: 상세 기능 명세의 49개 소기능 전체
- 초기 상태: 스켈레톤 24개, 미구현 17개, 대상 아님 8개
- `동작` 또는 `데모 검증`으로 판정된 기능: 없음

## 상태 판정 기준

| 상태 | 기준 |
|---|---|
| `미구현` | 백엔드 책임은 있으나 대응 코드나 실행 가능한 계약이 없다. |
| `스켈레톤` | API·DTO·테스트 골격은 있으나 고정 응답, 임시 데이터, 저장·검증 부재 등으로 실제 기능을 제공하지 않는다. |
| `동작` | 관련 자동화 테스트가 실제 비즈니스 동작을 검증하며 통과한다. 자동화가 어려운 외부 연동은 수동 검증 근거를 명시한다. |
| `데모 검증` | 프런트엔드와 연결한 사용자 흐름을 직접 시연한 근거가 있다. |
| `대상 아님` | 제품 소기능이지만 이 저장소가 책임지지 않는 프런트엔드 전용 동작이다. |

관련 코드나 환경이 바뀌면 `데모 검증`은 `동작`으로 되돌리고 다시 시연한다.

## 데모 핵심 종단 흐름

```text
성향 검사·세션 등록
→ 여행 기간 설정
→ AI 장소 추천·스와이프 선택
→ AI 코스 생성·수정·확정
→ 공유 링크 생성·팀원 합류
→ 탐험 시작·위치 확인·방문 인증
→ 팀 진행 상태·여행 기록·밝힌 지도 확인
```

`데모 핵심`은 구현 순서를 정하기 위한 표시다. `일반` 기능도 현재 MVP 범위에서
제외된 것은 아니다.

## 핵심 용어

아래 용어는 제품 화면과 기능에서 사용하는 의미다. 데이터 소유권과 상세 관계는
[백엔드 아키텍처](../architecture/backend.md)를 따른다.

| 제품 용어 | 의미 | 백엔드 표현 |
|---|---|---|
| 식별코드 | 같은 닉네임 사용자를 구분하고 간편 로그인에 사용하는 공개 번호 | `User.identifierCode` |
| 세션 | 사용자가 인증된 상태로 서비스를 이용·재진입하는 개념. 구체적인 토큰·세션 방식은 별도 인증 설계에서 정한다. | 인증된 `User` 컨텍스트 |
| 코스 | 선택한 장소의 방문 순서와 일정을 담고 생성·수정·확정되는 여행 계획 | `Course`, `CoursePlace` |
| 탐험 | 확정 코스를 여러 사용자가 함께 수행하는 시작·진행·완료 단위 | `Exploration` |
| 팀·팀원 | 탐험에 합류한 사용자 집합과 각 참여자. 별도 Team 쓰기 모델은 두지 않는다. | `ExplorationParticipant` |
| 방문 인증 | 참여자가 코스 장소에 도착했음을 위치 기준으로 확인하고 남기는 기록 | `Visit`, `VisitPhoto` |
| 여행 기록 | 코스와 탐험의 진행·완료 상태, 팀·개인 방문과 사진을 조회한 결과 | `Course`, `Exploration`, `Visit`, `VisitPhoto` 조합 |
| 밝힌 지도 | 방문 인증이 존재하는 장소를 누적해 보여 주는 지도 | `Visit` 기반 조회 결과 |

| 1.3.1 | 닉네임 입력 및 세션 등록 | 닉네임 검증, 식별코드·세션 발급과 저장 | 데모 핵심 | `스켈레톤` | `UserController`, `UserService.createNickname`; 임시 사용자·토큰과 고정 시각을 반환한다. |

## 현재 명세와 코드의 주요 불일치

- 최신 명세는 닉네임과 서버 발급 식별코드 로그인을 요구하지만 현재
  `LoginRequest`는 닉네임만 받으며 임시 access token을 반환한다.
- 질문 21개 중 7개 선별은 구현되지 않았고 성향 결과는 항상 `THINKER`다.
- 장소 추천은 성향·기간·DB·AI를 사용하지 않고 요청 limit에 맞춘 고정 장소를
  반환한다.
- 코스 생성·확정·조회는 저장, AI, 경로 계산이나 상태 전환 없이 임시 ID와 고정
  데이터만 반환한다.
- 공유 링크 합류, 탐험 활성화, 팀원 실시간 갱신과 위치 공유 동의 API가 없다.
- 방문 인증은 좌표 거리 검증·저장·WebSocket 전파 없이 성공 응답만 반환한다.
- 여행 기록은 DB 저장·조회 없이 임시 목록과 상세를 반환하며 밝힌 지도 집계는 없다.

## 논의 필요

제품 조건의 미정·상충 항목은
[제품 논의 필요](open-questions.md)를 정본으로 사용한다.
특히 추천 장소 수, 코스 완료 조건, 방문 인증 반경과 참여자별 기록 공개 범위는
백엔드 계약과 상태 모델에 직접 영향을 준다.

모든 기능을 현재 MVP에 포함했기 때문에 3개월 미만 일정에서 범위 위험이 크다.
우선 `데모 핵심` 종단 흐름을 완성하고, 범위가 변경되면 기능명세와 이 상태표를 같은
Pull Request에서 갱신한다.
