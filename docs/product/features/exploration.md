# 4. 팀 탐험 지도

[전체 기능 명세](../feature-spec.md) · [백엔드 MVP 상태](../mvp.md) · [논의 필요](../open-questions.md)

## 상세 기능

### 4.1 팀 합류

#### 4.1.1 공유 링크를 통한 팀 합류 및 코스 조회

- 적용 사용자: 전체 사용자 (공유 링크 접속자)

##### 상세 동작

- 공유 URL(`/explore/[코스ID]`) 접속 시 코스 ID로 서버에서 확정 코스 데이터 조회
- 신규 사용자(세션 없음): 닉네임 입력 → 식별코드 발급 모달 → 팀 합류
- 기존 사용자(세션 있음): 로그인(닉네임+식별코드) → 중복 합류 없이 팀원 자격으로 진입
- 유효하지 않은 코스 ID 접속 시: 6.1.1 참조
- 만료된 링크 접속 시: 6.1.4 참조
- 이미 진행 중인 코스가 있는 상태에서 합류 시: 6.4.1 중복 참여 차단으로 이동
- 모든 검증 통과 후 4.2.1 탐험 전 코스 보기 화면으로 이동
- 팀 내 동일 닉네임이 있는 경우 표시용 구분자 부여 (예: 김감자감자 (2))
- 구분 기준은 사용자 ID이며, 팀원 이탈 시에도 기존 표시는 유지

##### 백엔드·기획 참고

합류한 팀원 목록 조회 가능 여부 → [백엔드 확인] (4.2 선행)

### 4.2 탐험 전 코스 보기

#### 4.2.1 코스 미리보기 (지도 중심)

- 적용 사용자: 팀원 (탐험 시작 전)

##### 상세 동작

- 코스 합류 완료 또는 '내 여행'에서 진행 전 코스 카드 탭 시 진입
- 탐험 시작 전, 확정된 코스를 구경하는 상태
- 진입 시 코스에 포함된 장소 전체가 핀으로 표시된 지도를 우선 렌더링 (동선 폴리라인 포함)
- 하단 요약 패널: 코스명, 총 장소 수, 예상 소요시간
- '전체 목록 보기' 버튼: 클릭 시 타임라인 목록 시트 표시 (순서·장소명·예상 도착 시간)
- 지도 핀 또는 목록의 장소명 탭 시 4.4.2 장소 상세 시트 표시 (정보만, 방문 인증 버튼 없음)
- 하단 고정 '탐험 시작' 버튼 제공
- 이 상태에서는 방문 인증·지도 밝히기·주변 추천·내 위치 마커를 제공하지 않음

##### 백엔드·기획 참고

코스가 한눈에 들어오도록 지도 우선

탐험 전에도 코스 조회 API 사용 가능 여부 → [백엔드 확인]

#### 4.2.2 팀원 확인

- 적용 사용자: 팀원 (탐험 시작 전)

##### 상세 동작

- '팀 N명' 배지 탭 시 합류한 팀원 목록 표시
- 표시 항목: 팀원 닉네임 (탐험 전이므로 방문 수는 표시하지 않음)
- 합류 직후 본인이 팀에 정상 합류되었는지 확인하는 용도

##### 백엔드·기획 참고

팀원 목록 API → [백엔드 확인] (4.3.2와 동일 API 여부)

#### 4.2.3 성향 검사 진입

- 적용 사용자: 팀원 (탐험 시작 전)

##### 상세 동작

- 탐험 전 화면의 사이드바 메뉴에서 성향 검사(1.1.2)로 진입 가능
- 친구 코스에 합류한 신규 사용자가 자신의 여행 유형을 확인할 수 있도록 제공
- 검사 완료 후 탐험 전 코스 보기 화면으로 복귀

##### 백엔드·기획 참고

신규 화면 아님, 1.1.2 연결

#### 4.2.4 탐험 시작

- 적용 사용자: 팀원 (탐험 시작 전)

##### 상세 동작

- '탐험 시작' 버튼 클릭 시 동작
- 기기 위치 권한(GPS) 요청 다이얼로그 표시
- 권한 허용 시: 팀 탐험 세션 활성화 후 4.3.1 탐험 지도로 이동
- 권한 거부 시: "일부 기능이 제한됩니다 (방문 인증, 주변 추천 불가)" 안내 후 진행 허용
- 탐험 시작 이후 코스 상태는 '탐험 중(진행 중)'으로 전환
- 같은 Exploration의 활성 팀원은 누구나 탐험을 시작할 수 있으며 최초 요청만 성공

##### 백엔드·기획 참고

탐험 시작 전 합류를 허용할지, 활성화 이후에만 허용할지는 [결정 필요]다.
현재 4.2 탐험 전 코스 보기 흐름과 함께 기획에서 확정한다.

Course와 Exploration ID는 탐험 시작 전에 이미 발급됨. 탐험 시작 API와 소켓
payload는 후속 API 설계에서 확정

탐험 시작은 `BEFORE → ONGOING`의 1회성 전환이며 되돌릴 수 없음

### 4.3 탐험 지도

#### 4.3.1 현재 위치 표시

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- 팀 탐험 지도 화면 진입 시 Geolocation API로 현재 위치 취득 및 지도 마커 표시
- 위치 업데이트 주기: 실시간
- '내 위치로' 버튼 클릭 시 지도 중심을 현재 위치로 이동
- GPS 권한 거부 시: 위치 마커 미표시, 위치 기반 기능(방문 인증, 주변 추천) 비활성화 및 권한 재요청 배너 표시
- 위치 정확도 기준값 미달 시: 마커 표시 보류 및 '위치를 확인하고 있어요' 상태 안내 표시
- 광주 지역 밖일 때: 내 위치 마커는 정상 표시하되 주변 추천 API 호출은 하지 않는다 (지도 축소는 한국 전체까지 허용)
- 위치 공유 이벤트는 이전 전송 위치에서 10m 이상 이동했을 때 갱신한다.

##### 백엔드·기획 참고

광주 안/밖 판단은 백엔드가 담당한다.
주변 추천과 단순 방문 인증 요청은 REST API로 처리한다.
팀원 실시간 위치 공유와 방문 상태 실시간 갱신은 WebSocket 이벤트로 전달한다.
위치 전송 기준은 이전 전송 위치에서 10m 이상 이동했을 때로 한다.
GPS 정확도 기준값(m), 좌표 payload와 채널 계약은 별도 API 명세에서 확정한다.

#### 4.3.2 팀원 진행 상태 보기

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- 지도 화면 상단 또는 하단 팀원 현황 영역에 같은 코스에 합류한 팀원 목록 표시
- '팀 N명' 배지 탭 시 팀원 목록 상세 펼침
- 표시 항목: 팀원 닉네임, 개인별 방문 완료 장소 수 (예: "여행자 / 3개 완료")
- 실시간 업데이트 방식: WebSocket
- 팀원 위치 지도 공유 기능: 옵트인 방식으로 동의한 팀원만 지도에 마커 표시 (기본값 비공유)
- 위치 공유 옵트인 동의 UI 제공 (토글 또는 최초 동의 모달)
- 옵트인하지 않은 팀원: 목록에는 표시하되 지도 마커는 표시 안함

##### 백엔드·기획 참고

위치 공유 옵트인 상태는 서버가 참여자별로 저장. 팀원 목록 API, 실시간 갱신 payload와
소켓 채널 구조는 후속 API 설계에서 확정

#### 4.3.3 지도 밝히기 (방문 인증)

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- 코스 장소 핀 클릭 후 하단 시트의 '여기 왔어요 (지도 밝히기)' 버튼 클릭 시 동작
- 현재 GPS 위치와 대상 장소 좌표 간 거리 계산, 인증 가능 반경: [결정 필요 — 확정값 명기]
- 클라이언트 거리 계산은 버튼 활성화·거리 표시용이며, 실제 인증은 서버가 좌표를 재검증
- 반경 밖 상태: 인증 버튼 비활성 + 남은 거리 표시("약 Nm 남음"), 시도 시 "조금 더 가까이 가주세요" 토스트
- 반경 내: 방문 완료 처리 → 해당 장소·구역을 흑백에서 컬러로 전환
- [Before] 흑백·어두운 핀, 방문 버튼 활성 /
- [After] 컬러·밝은 핀, 방문 완료 배지, 버튼 비활성화
- 변경 사항을 팀 전체 화면에 실시간 전파 (WebSocket 이벤트)
- 같은 참여자의 동일 장소 중복 인증은 불가하다. 팀 전체 장소당 1회 제한 여부는 [결정 필요]다.
- GPS 권한 없는 경우 강제 인증 허용 여부 → [결정 필요] (무결성 재검토)
- 오류 처리: 6.2 참조

##### 백엔드·기획 참고

핵심 인터랙션.

인증 반경 확정값 → [결정 필요]
단순 방문 인증 요청은 REST API로 처리하고 서버가 거리를 재검증한다.
`visit:confirmed` 소켓 payload와 `visitedAt` 단위는 별도 API 명세에서 확정한다.

현재 ERD는 같은 팀원도 장소를 각각 한 번씩 인증할 수 있는 것으로 잠정 채택하며,
팀 전체 장소당 한 번만 허용할지는 기획 확인 필요

#### 4.3.4 탐험 지도 내 코스 상세 보기

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- 지도 화면 하단 패널 스와이프 업 또는 '코스 보기' 버튼 클릭 시 타임라인 표시
- 방문 완료 장소: '완료' 배지 + 컬러 표시 / 미방문 장소: 기본 표시로 시각적 구분
- 방문 완료 처리 기준: 4.3.3 지도 밝히기 실행 완료 시
- 타임라인 항목 탭 시 4.4.2 장소 상세 시트로 연결

##### 백엔드·기획 참고

3.1.2 타임라인 컴포넌트 재사용
방문 완료 상태 코스 조회 응답 포함 여부 → [백엔드 확인]

### 4.4 주변 탐색

#### 4.4.1 주변 장소 추천

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- '주변 장소 더보기' 버튼 클릭 시 동작 (자동 팝업은 트리거 조건 정의 후 적용, 또는 수동 버튼만 → [결정 필요])
- 현재 GPS 위치를 파라미터로 서버 API 호출하여 코스 미포함 근처 장소 수신
- 결과를 카드 목록으로 표시: 장소명, 현재 위치로부터의 거리, 카테고리
- 탐색 반경: 1km  / 최대 표시 수: 3개
- 장소 카드 탭 시 4.4.2 장소 상세 하단 시트 표시
- GPS 권한 없는 경우: 기능 비활성화 및 위치 권한 재요청 안내
- 광주 지역 밖: 주변 추천 버튼 비활성 + "광주에서만 주변 추천을 받을 수 있어요" 안내
- 반경 내 추천 장소 없는 경우: 6.3.1 참조

##### 백엔드·기획 참고

탐색 반경: 1km
최대 표시 수: 3개

주변 추천은 REST API로 요청한다. 자동 노출 조건과 세부 계약은 별도 명세에서 확정한다.

#### 4.4.2 장소 상세 보기 (탐험 지도 내)

- 적용 사용자: 팀원 (탐험 진행 중)

##### 상세 동작

- 지도 핀 탭 또는 주변 추천 카드 탭 시 하단 시트(Bottom Sheet) 형태로 표시
- 표시 항목: 장소 대표 이미지, 장소명, 주소, 운영시간, 카테고리 태그, 5.18 연관 의미(해당 시)
- 2.2.4 장소 상세와 동일 컴포넌트를 재사용하며, 노출 맥락에 따라 하단 액션만 분기
  - 탐험 전(4.2): 정보만 표시
  - 탐험 중(4.3/4.4): 지도 밝히기 버튼 (조건 충족 시 활성)
- 5·18 연관 의미는 사전 검수된 고정 텍스트만 사용
- 방문 완료된 장소: 상단에 "방문 완료" 배지 표시

##### 백엔드·기획 참고

5·18 연관 의미는 별도 전용 필드 없이 검수된 장소 상세 설명에 포함
