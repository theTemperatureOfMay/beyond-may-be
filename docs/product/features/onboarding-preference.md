# 1. 초기 진입 및 성향 검사

[전체 기능 명세](../feature-spec.md) · [백엔드 MVP 상태](../mvp.md) · [논의 필요](../open-questions.md)

## 상세 기능

### 1.1 온보딩 및 시작

#### 1.1.1 서비스 시작 화면 진입

- 적용 사용자: 전체 사용자

##### 상세 동작

- 서비스 루트 URL(`/`) 접속 시 서비스 소개 화면 렌더링
- 브라우저 로컬 스토리지에서 기존 세션 존재 여부 자동 확인
- 세션 없음 → 시작 화면 표시
- 세션 있음 + 확정 코스 없음 → 2.1.1 여행 기간 설정 화면으로 이동
- 세션 있음 + 확정 코스 있음 + 탐험 시작 전(`BEFORE`) → 4.2.1 코스 미리보기 화면으로 이동
- 세션 있음 + 확정 코스 있음 + 탐험 진행 중(`ONGOING`) → 4.3.1 탐험 지도 화면으로 이동
- 성향 결과만 있고 닉네임 없음 → 1.3.1 닉네임 입력 화면으로 이동
- 진입 시 세션 판별 완료 전까지 스플래시 화면 표시 후 분기
- 메인 그라디언트는 성향 결과 보유 시 해당 유형 컬러로 고정,
미보유 시 기본(주황) 컬러 표시
- 상단 좌측 공유 아이콘 클릭 시 서비스 링크 공유 시트 표시
- 세션 판별 API 오류 시: 6.2 공통 오류 정책에 따른다 (재시도 대상: 세션 판별 API / 보조 복귀 지점: 없음, 재시도만)

##### 백엔드·기획 참고

세션 상태에 따라 공통 응답 기준으로 분기한다.
세션 판별 API는 GET /api/session/status를 사용하며 판별 중에는 스플래시를 유지한다.
응답 필드와 예외 계약은 별도 API 명세에서 확정한다.

#### 1.1.2 성향 검사 시작

- 적용 사용자: 전체 사용자

##### 상세 동작

- 메인 화면 TAB(▼) 클릭 시 성향 검사 화면(`/onboarding`)으로 진입
- 진입 시 응답 배열을 빈 상태로 초기화 진행률 표시 바를 0%로 초기화하여 렌더링
- 질문 로딩 중 로딩(인트로) 화면 표시 → 질문 도착 시 첫 문항으로 자동 전환
- 첫 문항에서는 로딩 화면으로 되돌아갈 수 없음
- 기본 질문 수: 7개 (동점 시 질문 1개 추가)
- 새로고침·탭 종료 등 비의도적 이탈 시: 로컬 스토리지 임시 저장 응답으로
"작성 중이던 답변이 있어요" 다이얼로그 표시 (이어서 하기 / 새로 시작)
- 임시 저장 유효 기간: 24시간
- 질문 로딩(1.1.2) 실패 시 → 6.2 참조 (재시도 대상: 질문 조회 API / 복귀: 메인 화면)

##### 백엔드·기획 참고

질문은 21개 풀 중 기본 7개를 백엔드가 선별해 응답하고 동점이면 질문 1개를 추가한다.

프론트는 받은 배열 길이만 사용, 뼈대/가중치 구분 없음

뒤로가기 시 초기화: 별도 이슈로 분리

#### 1.1.3 사이드바 및 재진입

- 적용 사용자: 명세에 별도 기재 없음

##### 상세 동작

- 우측 상단 햄버거 아이콘 클릭 시 우측에서 사이드바 슬라이드 인
- [비로그인] 닉네임 + 식별코드 입력 → '시작하기' 클릭 시 이전 세션 복구
- [비로그인] 하위 메뉴: 서비스 소개 / 성향 검사 시작
- [로그인] 상단에 닉네임 + 유형 뱃지 표시
- [로그인] 메뉴: 내 성향 결과 / 진행 중인 코스 / 여행 기록 / 밝힌 지도
- [로그인] 하단: 로그아웃
- 로그인 실패 시 "닉네임 또는 식별코드가 올바르지 않아요" 통합 메시지 표시
- 요청 중에는 '시작하기' 버튼 비활성 + 로딩 표시
- 서버 오류(5xx)·네트워크 오류 시: 6.1.2 표시 (인증 실패 인라인 메시지와 구분)

##### 백엔드·기획 참고

로그인 시도 횟수 제한(rate limit) 백엔드 필요
에러는 닉네임/식별코드 구분 없이 동일 응답 (계정 열거 방지)

### 1.2 성향 검사 진행

#### 1.2.1 성향 검사 질문 진행

- 적용 사용자: 전체 사용자

##### 상세 동작

- 질문을 1개씩 순차 표시하며 각 질문에 4개의 선택지 제공
- 선택지 클릭 시 응답을 배열에 즉시 추가하고 다음 질문으로 자동 스크롤 전환
- 선택 시 고른 항목만 유지, 나머지 선택지는 dimmed 처리
- 진행률 표시 바 실시간 업데이트 (응답 수 / 전체 문항)
- 이전 질문으로 돌아가기 허용 여부: 허용
- 마지막 질문 응답 완료 시 결과 계산 화면(1.2.2)으로 자동 이동
- 각 선택지에는 사색러 / 미식러 / 예술러 / 기억러 4가지 유형별 가중치 점수 매핑
- 미응답 상태에서 스와이프/스크롤 시도 시 카드 바운스 애니메이션 +
하단 "답을 선택해주세요." 문구 노출 (1.5초 후 페이드아웃)

##### 백엔드·기획 참고

질문 데이터는 백엔드가 JSON 응답으로 제공

#### 1.2.2 성향 결과 계산 및 표시

- 적용 사용자: 전체 사용자

##### 상세 동작

- 전체 응답 배열의 유형별 가중치를 합산하여 최고 점수 유형을 최종 성향으로 결정
- 동점 처리 규칙: 질문 1개 더 추가해서 결정
- 결정된 유형에 맞는 결과 카드(유형명, 설명 텍스트, 대표 일러스트) 렌더링
- 결과값을 로컬 스토리지에 저장하여 닉네임 등록 전까지 유지
- 4가지 유형: 사색러 (성찰·역사) / 미식러 (음식·골목) / 예술러 (문화·예술) / 기억러 (민주화·추모)
- 결과 계산 중 뒤로가기 시도 시 "결과를 계산하고 있어요. 나가시겠어요?"
다이얼로그 표시 (나가기 / 기다리기)
- 로딩 문구는 경과 시간에 따라 단계별 전환
(0초: "당신의 여행 유형을 분석하고 있어요" → 완료 직전: "거의 완료되었습니다")
- 결과 계산 API 오류 시: 6.2 참조 (재시도 대상: 결과 계산 API / 복귀: 1.2.1)

##### 백엔드·기획 참고

유형별 비율 4종(사색러/미식러/예술러/기억러)을 결과 응답에 포함한다.
비율 계산 기준과 API 필드 상세는 별도 API 명세에서 확정한다.

#### 1.2.3 성향 결과 SNS 공유 카드 생성

- 적용 사용자: 전체 사용자

##### 상세 동작

- 결과 화면 하단 '이미지로 저장하기' 버튼 클릭 또는 하단 핸들바 드래그 업 시
저장 형식 선택 모달 표시
- 저장 형식: 화면 그대로 / 우표 엽서 (택 1)
- '저장' 클릭 시 이미지 생성 → 저장 완료 후 SNS 공유 시트 자동 노출
- 공유 대상: 카카오톡 / 시스템 공유 시트 / 링크 복사
- 인스타그램은 웹 직접 업로드 불가 → "이미지 저장 후 앱에서 업로드" 안내
- 링크 복사 시 navigator.clipboard API 사용, 미지원 브라우저 폴백 처리
- 다운로드 미지원 환경(iOS Safari 등): navigator.share 또는 "길게 눌러 저장" 안내 시트로 폴백
- 이미지 생성 오류 시: 6.2 참조 (재시도 대상: 카드 이미지 생성 / 복귀: 1.2.2)
- 결과 공유 URL 형식: https://[도메인]/result/[유형]
- 해당 페이지에 유형별 OG 메타태그 및 미리보기 이미지(1200×630) 적용
- 공유 링크로 진입한 신규 사용자는 성향 검사 시작 화면으로 연결

##### 백엔드·기획 참고

카카오 SDK 앱 키 발급 + 도메인 등록 필요
공유 카드 이미지 생성 결과는 서버에 저장한다.
이미지 생성 실행 주체와 접근 계약은 별도 API 명세에서 확정한다.

### 1.3 세션 등록

#### 1.3.1 닉네임 입력 및 세션 등록

- 적용 사용자: 전체 사용자

##### 상세 동작

- 성향 결과 화면 하단에 닉네임 입력 영역 표시
- 닉네임 유효성 검사: 최소 1자 / 최대 10자
- 빈 닉네임 제출 시 인풋 하단 오류 메시지 표시 ("닉네임을 입력해주세요")
- '시작하기' 클릭 시 서버에 세션 생성 요청
- 서버가 식별코드를 발급하여 응답 → "당신의 식별코드" 모달 표시
- 식별코드 모달: 코드 표시 + 복사 버튼 + "캡처해 두세요" 안내
- 세션 토큰과 식별코드를 로컬 스토리지에 저장
- 등록 완료 후 2.1.1 여행 기간 설정 화면으로 이동
- 식별코드 카드는 본인 보관용으로, 외부 공유 기능을 제공하지 않는다
- 세션 유지 중에는 사이드바에서 식별코드를 다시 확인할 수 있다
- 세션 생성 요청 오류 시: 6.2 참조 (재시도 대상: 세션 생성 API / 복귀: 1.3.1 유지)

##### 백엔드·기획 참고

닉네임 중복 허용 (표시용 이름).
실제 계정 식별자는 서버 발급 식별코드
식별코드 = 실제 계정 식별자, 서버 발급
식별코드 분실 시 계정 복구 불가 → 발급 시점 안내 강조 필수
